## 1. Общие сведения

Настоящие методические указания предназначены для проведения лабораторных работ по дисциплине «Веб-программирование» с использованием современного веб-фреймворка **FastAPI**.

Форма организации обучения: **лабораторный практикум со сквозным проектом**.

Сквозной проект означает, что студент не выполняет отдельные изолированные задания, а последовательно разрабатывает один программный продукт от лабораторной к лабораторной: от простого каркаса приложения до полноценного веб-сервиса с базой данных, аутентификацией, тестами, контейнеризацией и деплоем.

Рекомендуется использовать для студентов направлений, связанных с программной инженерией, информатикой, веб-разработкой и информационными системами.

## 2. Аннотация

В ходе выполнения лабораторных работ студент получает практические навыки разработки серверной части веб-приложений на языке Python с использованием фреймворка FastAPI.

В процессе обучения студент:

- создаёт REST API;
- использует валидацию данных с помощью Pydantic;
- подключает базу данных через SQLAlchemy;
- управляет схемой базы данных с помощью Alembic;
- реализует связи между сущностями;
- добавляет пагинацию, фильтрацию и сортировку;
- реализует аутентификацию и авторизацию;
- работает с файлами;
- использует фоновые задачи;

- применяет архитектурные принципы;
- упаковывает приложение в Docker;
- настраивает CI/CD и деплой.

Итогом обучения является готовый веб-сервис, размещённый в репозитории и пригодный для демонстрации в качестве курсового или учебного проекта.

# Лабораторная работа №1  
## Каркас FastAPI-приложения и базовый REST API

## 1. Цель работы

Получить практические навыки создания веб-приложения на FastAPI, настройки маршрутов, использования Pydantic-моделей и реализации базового CRUD-интерфейса без базы данных.

## 2. Продолжительность

4 академических часа.

## 3. Теоретические положения

FastAPI — это современный высокопроизводительный фреймворк для создания веб-API на Python. Он использует аннотации типов, автоматически генерирует документацию и поддерживает асинхронную обработку запросов.

Основные понятия:

- **маршрут** — адрес и HTTP-метод, которые обрабатывает сервер;
- **эндпоинт** — функция, обрабатывающая запрос;
- **запрос** — данные, передаваемые клиентом;
- **ответ** — данные, возвращаемые сервером;
- **статус-код** — результат обработки запроса;
- **валидация** — проверка корректности данных.

## 4. Задание

Разработать каркас веб-приложения и реализовать базовый CRUD для сущности `Task`.

Данные хранить в памяти приложения.

## 5. Обязательные эндпоинты

```text
GET    /api/v1/tasks
GET    /api/v1/tasks/{task_id}
POST   /api/v1/tasks
PUT    /api/v1/tasks/{task_id}
DELETE /api/v1/tasks/{task_id}
```

## 6. Порядок выполнения

1. Создать директорию проекта.
2. Создать виртуальное окружение.
3. Установить зависимости:

```bash
pip install fastapi uvicorn
```

4. Создать файл `main.py`.
5. Создать приложение:

```python
from fastapi import FastAPI

app = FastAPI(title="Task Manager API")
```

6. Создать схему задачи.
7. Реализовать временное хранилище задач в виде словаря или списка.
8. Реализовать маршруты.
9. Запустить сервер:

```bash
uvicorn app.main:app --reload
```

10. Проверить документацию по адресу:

```text
http://127.0.0.1:8000/docs
```

## 7. Требования к реализации

1. Использовать версию API `v1`.
2. Все входные данные должны проверяться через Pydantic.
3. При создании задачи возвращать статус `201`.
4. При удалении задачи возвращать статус `204`.
5. Если задача не найдена, возвращать статус `404`.
6. При ошибке валидации автоматически возвращать статус `422`.
7. Код должен быть разбит на модули.

Пример структуры:

```text
app/
    main.py
    api/
    schemas/
    services/
```

## 8. Пример модели

```python
from pydantic import BaseModel

class TaskCreate(BaseModel):
    title: str
    description: str | None = None

class TaskRead(BaseModel):
    id: int
    title: str
    description: str | None
```

## 9. Требования к отчёту

Отчёт должен содержать:

- цель работы;
- структуру проекта;
- листинг основного кода;

- примеры запросов;
- примеры ответов;
- выводы.

3. Что такое статус-код ответа?

## 1. Цель работы

## 2. Продолжительность

4 академических часа.

## 3. Теоретические положения

**Базы данных** используются для долговременного хранения информации. В веб-приложениях чаще всего применяются реляционные базы данных.

**SQLAlchemy** — это библиотека для работы с базами данных в Python, предоставляющая ORM-возможности.

**Модель** — класс, отображаемый на таблицу базы данных.

**Сессия** — объект, через который выполняются операции с базой данных.

## 4. Задание

```text

```

```text
PostgreSQL
```

```text
GET    /api/v1/tasks
GET    /api/v1/tasks/{task_id}

```

## 6. Порядок выполнения

1. Установить зависимости:


2. Создать файл настройки подключения к базе данных.

6. Проверить операции через `/docs`.

## 7. Требования к реализации

1. Использовать асинхронный движок базы данных.
2. Использовать Pydantic-схемы для входных и выходных данных.
3. Модель базы данных должна быть отделена от Pydantic-схемы.
4. Подключение к базе данных должно браться из переменной окружения.
5. Запрещается хранить данные только в памяти.

## 8. Пример файла окружения


# Лабораторная работа №3  
## Управление схемой базы данных с помощью Alembic

## 1. Цель работы

Получить навыки управления структурой базы данных с помощью миграций.

## 2. Продолжительность

4 академических часа.

## 3. Теоретические положения

**Миграция** — это файл, описывающий изменения структуры базы данных.

**Alembic** — инструмент для управления миграциями в проектах на SQLAlchemy.

- создавать таблицы;
- изменять таблицы;
- удалять таблицы;
- добавлять колонки;
